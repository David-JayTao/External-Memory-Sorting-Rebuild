# Week 5 验收

依据课件第 39–44、59–60、72、78 页。实现 Thread/join、Loser Tree、Replacement Selection、最优二路归并树，以及读算写三阶段 Run 生成流水线。第 79–80 页的动态调度和并行 K 路归并属于后续周。

小例子 M=3、输入 [4,1,3,2,6,0,5,2]：输出 1 后读入 2，2 ≥ 1，留在当前段；输出 3 后读入 0，0 < 3，归入下一段。形成 [1,2,3,4,5,6] 和 [0,2]；最终归并为 [0,1,2,2,3,4,5,6]。最优计划的独立长度示例 [1,2,3,10] 成本为 25，普通平衡配对为 32。

核心成员：LoserTree.entries_ 是叶子记录及有效/段标记，losers_ 保存败者下标，champion_ 保存冠军；SelectionOutput.current_run_ 记录正在写的段编号；流水线 active_input/active_output 决定活动缓冲，stage 标识当前同步轮次。

1. **败者树保存什么？** 内部结点保存比较失败的叶子下标，冠军另存；替换冠军后沿路径与旧败者重赛。
2. **冻结是怎么实现的？** 新值小于刚输出值就让 run_number 加一；比较时先按段编号，再按值排序。
3. **置换选择一定产生 2M 长的段吗？** 不是；约 2M 是随机数据的典型情况。升序可更长，逆序通常为 M。
4. **最优计划为什么合并短段？** 短段多搬运、长段少搬运可降低带权路径长度；对固定二路记录数成本模型是最优的。
5. **流水线三个线程分别做什么？** 输入线程读下一块，主线程计算当前块，输出线程写上一块；join 后交换双缓冲。
6. **为什么不用 mutex？** 同一阶段线程操作不同缓冲和不同文件对象，只有 join 后才交换所有权，没有并发修改共享内容。
7. **异常时如何结束？** 辅助线程捕获异常，主线程 join 所有已启动线程后重新抛出；不使用可能因参与者退出而卡住的屏障。
8. **EOF 后为什么还循环？** 树里和待写缓冲可能还有记录，必须排空才能 finish；测试核对 Run 边界及最终排序，防止丢尾。

2026-10-29 实际验收：WSL GCC 15.2、CMake 4.4.4，Debug 全回归 3/3 通过（28.59 秒），Release 全回归 3/3 通过（25.56 秒），两种 Demo 都输出上述两条 Run、最终结果和 32/25 成本。测试含败者树线性扫描对照、最优成本穷举、M=1/3/8、B=1/2/5 的串并行逐条与段边界比较，以及完整置换选择 → 最优计划 → 外排序链路。

输入/计算/输出/第二线程启动故障分别在阶段 0、1、3 注入，12 条异常路径均抛回调用者；半成品被拒读且可删除，之后重新调用正常。CTest 设 180 秒超时，避免卡住时把等待误认为通过。
