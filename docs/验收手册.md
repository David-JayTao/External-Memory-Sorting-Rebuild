# 验收手册

先阅读[课程讲义](课程讲义.md)，再依次运行三个 Demo。每周范围和问答见 [Week 3](验收/Week3.md)、[Week 4](验收/Week4.md)、[Week 5](验收/Week5.md)。本手册用于口头定位，不代替完整讲义。

## 类型与调用关系

| 类型 | 保存什么 | 由谁调用、会修改什么 |
|---|---|---|
| [FileHeader / RunInfo](../include/external/run_file.h#L9-L21) | 文件布局；单段 ID、条数、字节范围 | RunWriter 写磁盘，RunFile 校验并保存在内存 |
| [RunFile](../include/external/run_file.h#L24-L35) | 输入流、header_、runs_ | InputBuffer 调 read_block；改变文件游标，不改文件内容 |
| [RunWriter](../include/external/run_file.h#L37-L50) | 输出流、当前段、文件头、状态标记 | OutputBuffer 和上层管理段边界；创建新文件、写记录与元数据 |
| [InputBuffer](../include/external/buffer.h#L6-L17) | 文件引用、Run ID、缓存、下次读位置、缓存游标、有效数 | Scan 按需补读；返回下一记录或 false |
| [OutputBuffer](../include/external/buffer.h#L18-L28) | writer_、values_、buffered_count_ | Put 接记录；flush 将有效记录交给写者 |
| [RecordStream](../include/external/run_generation.h#L7-L17) | file_、buffer_capacity_、next_run_、input_ | 串联所有 Run，给初始生成算法提供流式输入 |
| [MergePlanNode / MergePlan](../include/external/merge.h#L11-L24) | 子结点下标、输入与输出路径、长度、成本、状态；结点数组和 root | 普通/最优计划构造，execute_plan 递归执行并更新状态 |
| [LoserTree](../include/external/loser_tree.h#L11-L23) | entries_、losers_、leaf_count_、champion_ | ReplacementSelection 用 top 读冠军、replace_winner 重赛 |
| [ReplacementSelection](../include/external/replacement_selection.h#L10-L18) | tree_ | emit 接可选新值，返回带段编号的旧冠军 |
| [SelectionOutput](../include/external/replacement_selection.h#L21-L31) | writer_、output_、run_open_、current_run_ | Put 识别段切换，finish 完成文件 |
| [pipeline_runs](../src/pipeline.cpp#L35) | 两组输入/输出块、活动下标、阶段号、线程及异常 | 主线程计算，两个辅助线程预读和写出；join 后交换 |

`unique_ptr<InputBuffer>` 只负责当前缓冲的生命周期；`optional<Value>` 区分“读到了 0”和“没有新输入”；`exception_ptr` 将线程异常带回主线程。没有通用工厂或线程池。

## 核心函数速查

| 函数 | 输入与结果 | 关键不变式 |
|---|---|---|
| [Scan](../src/buffer.cpp#L10) | 返回下一记录，EOF=false | 游标不超过有效数 |
| [Put / flush](../src/buffer.cpp#L24) | 暂存一条或写出缓存 | 不跨 Run 遗留未刷出数据 |
| Search | 返回首次命中记录下标或 nullopt | 顺序扫描，不依赖输入有序 |
| [generate_runs](../src/run_generation.cpp#L20) | 输入文件 → 多个有序 Run | 每批记录数 ≤ M |
| [merge_two](../src/merge.cpp#L77) | 两个 Run → 单 Run 文件 | 每次选小并只推进一个输入 |
| [execute_plan](../src/merge.cpp#L144) | 计划 → 最终文件 | 先子后父，不删除叶子输入 |
| [optimal_plan](../src/optimal_merge.cpp#L9) | 各 Run 长度 → 最优二路计划 | 每次合并最短两段 |
| [replace_winner](../src/loser_tree.cpp#L49) | 新叶子 → 新冠军 | 只沿原冠军路径重赛 |
| [emit](../src/replacement_selection.cpp#L7) | 新值或 EOF → 带编号的输出值 | 新值 < 输出值则编号加一 |

## 典型验收顺序

1. 按 README 完成 Debug 和 Release 构建与 CTest 全回归。
2. 运行 Week 3 Demo，解释三段目录、空段、缓存容量 2 和 Search 返回 1。
3. 运行 Week 4 Demo，先手算 M=3 的三个 Run，再解释成本 14 和递归执行顺序。
4. 运行 Week 5 Demo，解释败者树冠军从 1 变 2，置换选择为什么把 0 冻结到下一段；比较串行与流水线 Run。
5. 解释长度 [1,2,3,10] 的普通成本 32、最优成本 25；说明它是搬运量估计，不是实测耗时。
6. 打开测试中的 `test_pipeline_failures`，说明四类故障都先 join 再抛出，后续新调用正常。
7. 查看 `git log --graph --decorate --oneline --all` 与 `git tag -n`，展示各周独立快照。

每个 Demo 接受一个新的输出路径或目录；重复运行请换名字，程序不会覆盖已有结果。最终有序文件仍采用相同 Run 文件格式，只有一个 Run。测试全量加载小样本是验证用法，生产排序路径使用有限缓冲。
